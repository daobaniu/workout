# 燃脂搭子 · 产品演进计划书

> 目标：把当前 Demo 逐步打造成「真正可用、可留存、可商业化」的减脂健身 Agent 产品。  
> 原则：**先留存与纠错，再精度；先单 Agent + Tool 做稳，再谈多 Agent；代码由你实现，本文只作施工图。**  
> 更新日期：2026-09-11

| 能力 | 状态 |
|------|------|

## 二、优先级总览

按 **P0 → P3** 推进。同一阶段内按序号做；未完成 P0 不建议跳去拍照识别 / 多 Agent / 原生 App。

| 优先级 | 阶段名 | 核心目标 | 建议周期 |
|--------|--------|----------|----------|
| **P0** | Demo 可用化 | 用得顺、错了能改、失败看得懂 | 1–2 周 |
| **P1** | 留得住 | 大盘 + 可交互卡片 + 周反馈 | 2–4 周 |
| **P2** | 算得准一点 | 食物库 + 训练负荷数据 + 偏好记忆 | 3–5 周 |
| **P3** | 能上线 / 能卖 | Auth、云库、配额、合规、付费点 | 4–8 周 |
| **P4** | 增强（可选） | 拍照/语音、多 Agent、App、向量库 | 视业务再开 |

```mermaid

  P1 --> P2[P2_精度]
```

## 三、分阶段计划（含验收标准）

### P0 · Demo 可用化（最高优先）

目标：自己愿意天天用；朋友试用不会因「估错/报错/刷新丢对话」立刻弃用。

| 序号 | 任务 | 做什么 | 验收标准 |
|------|------|--------|----------|
| P0-1 | 环境与模型文档 | `.env` / DeepSeek 等配置写清；example 不放真 Key | 按 README 能跑通对话 |
| P0-2 | 错误可感知 | 聊天失败展示可读原因（网络/Key/模型），避免笼统 An error occurred | 故意配错 Key 能看懂下一步 |
| P0-3 | 饮食纠错 | 卡片或输入可改热量/宏量并写回 DB | 估错后 1 步修正，概览同步变 |
| P0-4 | 训练勾选完成 | 今日训练清单可勾选动作/整课完成 | 勾选后 WorkoutLog 更新，概览显示完成 |
| P0-5 | 热量预算可见联动 | 改档案身高体重活动量后预算重算且 UI 说明下限 | 用户能理解数字为何变/不变 |
| P0-6 | 快捷入口 | 首页按钮：「记一餐」「要训练」「今天吃什么」预填对话或直调 | 不全靠想得到怎么说 |
| P0-7 | 移动端基本可用 | 主界面手机可顺畅记与看 | 真机浏览器走通建档→记餐→推练 |

**P0 明确不做：** 登录、拍照、LangGraph、向量库、体脂主功能。

---

### P1 · 留得住（体验与习惯）

目标：用户每周至少打开几次，能「看见自己的进度」。

| 序号 | 任务 | 做什么 | 验收标准 |
|------|------|--------|----------|
| P1-1 | Dashboard 热量+宏量 | 环形/进度条：热量与蛋白/碳/脂 | 今日摄入与预算一眼可见 |
| P1-2 | 体重趋势图 | 近 2–4 周折线 | 有 ≥2 个体重点即可出图 |
| P1-3 | Generative UI 增强 | 饮食卡、训练卡可编辑、可确认写入 | 不只 Markdown |
| P1-4 | 结构化偏好字段 | 忌口、伤病规避、器械偏好（表字段或 JSON） | 建档/对话可写入，推餐推练会读 |
| P1-5 | 周小结（规则优先） | 每周体重变化 + 记录天数 + 一句建议；可先定时或手动「生成本周小结」 | 连续不掉秤时提示检查饮食/预算 |
| P1-6 | 对话短持久化（可选） | 最近 N 条落库，刷新可恢复；发给模型仍做窗口裁剪 | 刷新不丢最近对话，Token 不爆炸 |
| P1-7 | 空状态钩子 | 今日未记饮食/未训练时的引导文案 | 打开 App 知道下一步 |

**P1 明确不做：** 多 Agent 路由、完整 USDA 对接、付费系统。

---

### P2 · 算得准一点（领域壁垒）

目标：减少幻觉，让「下次推练」有依据。

| 序号 | 任务 | 做什么 | 验收标准 |
|------|------|--------|----------|
| P2-1 | 精简食物库 | 接入或自建常见食物表（优先中国常见食物）；记餐「查库优先，LLM 兜底」 | 鸡胸/米饭等常见项偏差可控 |
| P2-2 | 记餐置信度 | 低置信要用户确认再写入 | 奇怪组合不静默乱写 · **已完成** |
| P2-3 | 训练负荷模型 | 组数/次数/重量（可选 RPE）入库 | 历史可查 · **已完成** |
| P2-4 | 渐进超负荷建议 | 推课时读取上次同动作成绩给建议 | 文案含「上次 X，今日建议 Y」 · **已完成** |
| P2-5 | 目标模式 | 减脂/维持/增肌，缺口策略不同 | 建档可选，预算公式分支正确 · **已完成** |
| P2-6 | 动作库结构化增强 | GIF/要点/替代动作进 DB 或静态模块；检索按肌群器械 | 少靠临时搜动作细节 |
| P2-7 | 长期画像更新 | 对话中识别「不吃牛肉」等 → 写偏好表 | 下次推餐自动避开 · **已完成** |
| P2-8 | 基础单测 | 热量公式、预算下限、关键 Tool 入参 | CI 或本地 test 通过 · **已完成** |

**P2 注意：** 联网搜索继续定位「补充说明」，不替代模板排课与食物库。

### P3 · 能上线 / 能商业化

目标：多人可用、数据同步、成本可控、合规能上。

| 序号 | 任务 | 做什么 | 验收标准 |
|------|------|--------|----------|
| P3-1 | Auth | Clerk / Auth.js 等 | 注册登录登出 |
| P3-2 | Postgres | Neon/Supabase 等；SQLite 迁移方案 | 多设备同账号数据一致 |
| P3-3 | 数据按 userId 隔离 | 所有表带用户维度 | 无越权读写 |
| P3-4 | 成本护栏 | 每用户日请求/Token/搜索次数上限 | 超限有提示 |
| P3-5 | 可观测 | 服务端日志：模型错误、Tool 失败率 | 能排查线上问题 |
| P3-6 | 合规文案 | 用户协议、隐私政策、健康免责（强化展示） | 关键页可见 |
| P3-7 | 付费点设计并实现最小版 | 建议：免费基础记账+配额；会员提高额度/周报/进阶计划 | 能完成一笔测试订阅或发卡 |
| P3-8 | 北极星指标埋点 | 周记录天数、D7 留存等 | 能导出或后台看到 |

**商业化最小闭环建议**  
免费：记饮食、基础推练推餐、有限对话次数。  
会员：更高配额、周报、渐进超负荷、（此后再放）拍照识别。

## 四、四个维度对照（防跑偏）

### 1. 功能与 UX
- 优先：大盘、纠错、卡片交互、快捷入口、移动端  
- 靠后：体脂主曲线、原生 App、复杂动画  

### 2. AI Agent
- 优先：单 Agent + Tool、结构化写库、偏好表、窗口裁剪、确认写入  
- 靠后：Router 多 Agent、全域向量化、把全文聊天当长期记忆  

### 3. 业务闭环
- 优先：预算公式清晰、周反馈、训练负荷、目标模式  
- 壁垒顺序：依从性（天天记）→ 反馈环 → 渐进超负荷 → 更精食物库  

### 4. 工程
- 优先：错误可读、env 校验、user 隔离、限流、单测公式  
- 靠后：重型评测平台、过度微服务  

### 5. 补充维度：商业与信任（原稿常缺）
- 付费点、留存指标、免责与合规、坏案例纠错入口、内容版权（动作示范从哪来）

## 五、上下文与存储策略（单独钉死）

| 数据类型 | 是否持久化 | 是否每次塞给模型 |
|----------|------------|------------------|
| 档案 / 偏好 / 饮食 / 体重 / 训练日志 | **必须** | 用 Tool 按需读，或注入短摘要 |
| 完整聊天记录 | P1 可选短留存 | **否**，只带最近 N 轮 |
| 周摘要一句话 | 建议 P1/P2 | 可注入 |

原则：**结构化事实进库；对话窗口要短；搜索与食物库各司其职。**

## 六、每阶段「完成定义」（Definition of Done）

- **P0 完成：** 你连续 7 天自己愿意用主路径（建档→记餐→推练→改错）。  
- **P1 完成：** 外部 3 人试用，无需你讲解能完成记餐与看趋势；至少 1 人第二天还打开。  
- **P2 完成：** 常见食物估算有库可依；推练能引用上次重量次数。  
- **P3 完成：** 两账号隔离正确；有配额；有隐私与免责；能解释怎么赚钱。  
- **P4：** 有明确指标证明「贵能力」能换留存或付费再开工。

## 七、风险与红线

1. **不宣传疗效**，不做医疗/康复处方。  
2. **极端节食、进食障碍倾向** → 引导专业帮助，不继续「优化缺口」。  
3. **Key 与隐私**：密钥不进 example/仓库；用户健康数据需隔离与最小化。  
4. **成本：** 未做限流前不要对公网放开无限对话/识图。  
5. **抵制范围蔓延：** 想做 LangGraph / 小程序前，先问「P0/P1 验收过了吗」。
